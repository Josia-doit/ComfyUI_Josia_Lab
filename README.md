# ComfyUI_Josia_Lab

JosiaNodes 的**实验包**：临时节点与未定稿功能的独立试验田，与主节点包 `ComfyUI_JosiaNodes` 分离，
节点可以随时增删，不影响正式包。

> 实验性质：节点没有稳定性承诺，接口与行为可能在下一个版本调整。

## 安装

把整个目录放进 ComfyUI 的 `custom_nodes/` 下即可，无需额外依赖。

```
ComfyUI/custom_nodes/ComfyUI_Josia_Lab/
```

## 当前节点

### JosiaQwenAccel · QwenImage2.1 加速 LoRA 适配器

给 Qwen-Image 2.1 的两个官方加速 LoRA 做适配：选好文件与类型，加载方式、采样器、sigma 都由节点内部
按类型决定，不需要手工配置。

分类：`⚡️Josia实验区/Qwen加速`

**必填**

| 控件 | 说明 |
| --- | --- |
| 选择LoRA | `loras` 目录下的 `.safetensors` 下拉；最上面常驻一项「使用官方 Qwen Image 2.1 Turbo 模型（不挂 LoRA）」是特例，选它不加载任何 LoRA。其它文件选哪个就按上面那个类型怎么加载它；文件随便改名、换版本都不影响节点。 |
| 加速LoRA类型 | `Fun PDD（4 步）` / `Viggle Turbo（6 步）` / `官方 Turbo（8 步）`。切这里换加载方式、采样器与 sigma，不动你选的那个文件。 |
| 采样器 | Fun PDD 与官方 Turbo 都只放开 euler；Viggle 可以另外试试。 |

**可选输入**

| 端口 | 说明 |
| --- | --- |
| model | 选填。不接就只把采样器与 sigma 传下去，方便单独接一个预览节点看数值。 |
| sigmas | 选填。不接就按类型用内置的那套；接进来的 SIGMAS 优先。 |
| latent | 选填。喂给采样器的那个 latent，Viggle 用它按分辨率换算 sigma；Fun PDD 与官方 Turbo 无视它。 |

**输出**：`model` / `sampler` / `sigmas`

**两条路线**

- **Fun PDD（SLMONKER / ComfyUI-QwenImage21-Fun-PDD，4 步）**
  不是普通 LoRA：除常规 lora_A/lora_B 外还带若干整参数与 4 个「按步数选头」的输出头，
  只能走官方那套 patch 流程加载，采样固定 euler、sigma 为官方成品值。
  需要**原生 Qwen-Image-2.1 基础模型**（不是 2509 / 2511，也不是 Diffusers 转换的），
  不接受参考 Latent。

- **Viggle Turbo（6 步）**
  普通 LoRA，官方建议走 forward 旁路加载而不合并进权重（bf16 融合只剩约 70% 更新量，
  int8 再量化还会引入约 4 倍噪声），因此权重一格不动，用 hook 在 forward 后补上 LoRA 贡献。
  sigma 用的是官方 `ViggleTurboSigmas` 输入框那串 t 值，运行时按参考 Latent 的尺寸换算成真正的 sigma
  （末位补 0），不接 Latent 就按 1024² 兜底。

- **官方 Turbo（8 步）**
  不是 LoRA，是 Qwen 官方发布的 Qwen-Image-2.1-Turbo 检查点。在「选择LoRA」里选最上面那项
  「使用官方 Qwen Image 2.1 Turbo 模型（不挂 LoRA）」，就等于把官方 Turbo 检查点当基础模型、
  节点不加载任何 LoRA，只把 model 原样透传、把官方 8 步 sigma（检查点 `model_index.json` 里的
  `sample_sigmas`，末位补 0 凑 8 步）和 euler 采样器交给下游。CFG 保持 1、不要负面提示。

**接线要求**

- 三个输出接 `SamplerCustom`，**CFG 保持 1**，不要接负面提示。
- 用哪个类型就接哪个 LoRA；文件与类型的对应关系由你决定，节点不会替你换文件。
- 内置 sigma 已经与该类型绑定，不要从别处接 sigma 进去 —— 缺文件、不配套时节点会直接点名报错。

### Josia框选编辑 · 经典模式的边界框编辑器

分类：`⚡️Josia实验区/框选编辑`

**它是什么。** ComfyUI 官方的「创建边界框 Create BoundingBoxes」是给 FLUX 3 / MOSS-Image 那类
「按区域描述出图」节点喂框的，画框要靠 2.0 前端那块全屏框编辑器——经典（1.0）模式下那个控件
根本不渲染。本节点是它在经典模式下的平替：自己实现一块「框选面板 + canvas」，框照画、数据照产，
拿到经典模式一样用。输出数据与官方节点逐字段对齐，下游哪个节点认官方的框，就照样认这里的框。

**面板端口／选项**

| 名称 | 作用 |
| --- | --- |
| 画布宽度 / 画布高度 | 框所在的**像素网格**。框内部按 0~1 分数存，像素坐标 = 分数 × 画布尺寸。按你要出图的目标分辨率填；接上底图或编辑器里选底图时会自动对齐到底图尺寸。 |
| 底图（可选 · IMAGE） | 画布和预览的背景图。接了它，框的像素坐标就贴这张图的尺寸走；出图也更好对位。 |
| 框数据（隐藏 · 自动保存） | 编辑器画好的框序列化后存在这里，随工作流一起存，不用手动管。 |

点「打开框选编辑器」后：

- **画框**：在空白处按下拖拽即出新框；拖角缩放、框内拖动移动、滚轮缩放选中框。**先放背景元素、最后放前景**（框的顺序＝叠加层级，和官方一致）。
- **右侧属性**：`类型`（物体 obj / 文字 text）、`文字`（text 类型才会渲染的字）、`描述`（简短名词，如 `dress`/`logo`——这一项就是喂给出图节点的内容）、`颜色`（框颜色，会带进颜色板）、`位置`（像素坐标只读回显）。
- **底栏**：新建框 / 删除选中 / 清空全部 / 适应窗口 / 底图（选本地图当底图）/ 除底图。编辑器内选的底图会把画布宽高对齐过去，并记住，重开还在。

**四个输出都能干什么**

| 输出 | 内容形态 | 典型用法 |
| --- | --- | --- |
| 预览图 `IMAGE` | 把框画在灰底或底图上的预览 | 接预览 / 保存节点快速核对框位；配合「边界框」出裁切预览。 |
| 边界框 `BOUNDING_BOXES` | 像素整数框 `[[{x,y,width,height}]]`（双层 list） | 接只吃「图像像素矩形」的节点：裁切区域、VAE 编码区域、inpaint 区域、按块处理。也可回喂官方框输入当复用的底稿。 |
| 元素 `ARRAY` | `[{type, bbox:[ymin,xmin,ymax,xmax]（0~1000 整数）, text, desc, color_palette}]` | 这是 **Ideogram / FLUX 3 风格的分区描述格式**，喂 FLUX 3、MOSS-Image、字节那类带「框输入」的出图节点，让它在指定区域按你的 `desc`/`text` 出对应内容。 |
| 元素JSON `STRING` | 上面那份的元素，JSON 字符串 | 想自己拼提示词、存成文件（接文本保存节点）、或喂给只吃 STRING 框输入的节点时用；也方便先导出再手工编辑。 |

**什么工作流会用到**

- **分区受控出图**：框选编辑 → `元素` → FLUX 3 / MOSS / bytedance 的框输入，再配一段把各区 `desc` 串起来的提示词，指定区域出指定物体/文字。
- **分区局部重绘**：框选编辑 → `边界框` → 对应区域的裁切 / VAE 编码 → 只重画这一块再贴回。
- **版面/海报打稿**：用「边界框」读出像素坐标，接分批裁切 + 分别出图 + 拼合的流水线。
- **框复用**：把 `边界框` 接回官方「创建边界框」的 bboxes 输入改一版（官方能认），或把 `元素JSON` 存盘当模板。
